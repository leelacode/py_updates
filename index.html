Python 3.15 is now in release-candidate mode

Python 3.15.0rc2, released on September 1, is the final planned release candidate, with roughly 144 bug fixes, build improvements and documentation changes since rc1. The Python core team has scheduled the final 3.15.0 release for October 1, and the ABI is not expected to change from this point. For application developers, this is a good time to run compatibility tests against 3.15 without treating it as a production default yet. For library maintainers, the practical priority is building and testing wheels now, because wheels built against the release candidates are expected to remain usable across the 3.15 series.

Packaging governance is becoming more explicit

The new Python Packaging Council held its inaugural meeting on September 18, with notes published on September 23. The first meeting was mostly about operating details: a likely repository in the Python organization, weekly meetings to start, and coordination with the PSF. There are no immediate user-facing packaging changes in those notes, but the larger signal is important: packaging is receiving a dedicated governance structure rather than being handled only through scattered project-level decisions. Over time, that should make ecosystem-wide discussions about installers, indexes, build backends and tooling easier to coordinate.

NumPy 2.5.3 improves Python 3.15 readiness

NumPy 2.5.3, released September 6, supports Python 3.12 through 3.15 and includes fixes around the ongoing StringDType work. Converting invalid UTF-8 byte strings to StringDType now raises TypeError instead of preserving invalid bytes and risking undefined behavior later. Another fix prevents stale masked-array fill values from surviving dtype-changing operations. If your stack includes scientific Python, this is a sensible maintenance update to pair with early 3.15 testing.
